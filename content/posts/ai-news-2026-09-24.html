Agentic coding settles into the tools you already use, local hardware takes on real agent work, and open models keep pushing into the physical world. Seven stories, each summarized in our own words with a link to the original reporting.

Android Studio opens to any coding agent with Bring Your Own Agent

Google announced Bring Your Own Agent for Android Studio, letting developers plug in their preferred coding agent, including options from Anthropic, OpenAI, and Google, inside the IDE. The IDE supplies project-graph context, build setup, and platform details over the Agent Client Protocol, plus native hooks for build diagnostics, Compose previews, SDK tools, and emulator control. Agents can read and edit files, run commands and tests, delegate to subagents, and keep long sessions with project skills, while granular permissions gate riskier actions.

The practical win is flexibility without losing IDE context: swap agents when quota or quality dips, keep one workflow, and let the agent test against the real project. The feature is in preview on the canary channel, so confirm availability and plan support before standardizing a team on it.

Antigravity SDK gains offline local-agent support with Gemma 4 26B

Google added local-model support to the Antigravity SDK, starting with Gemma 4 26B A4B running through LiteRT for fully offline agentic assistance on the local GPU. The same SDK can also drive any OpenAI-compatible local server such as Ollama, LM Studio, or vLLM without changing orchestration code. Example workflows include a cloud planner paired with a local model swarm that keeps most tokens on-device, plus a fully local loop that reproduces issues, drafts fixes, and validates against regression suites.

Local-first teams should look at the hybrid pattern: plan in the cloud, execute routine work offline for privacy and cost, and keep proprietary code on the machine. Verify VRAM and driver requirements on your own hardware, since local GPU behavior varies more than API behavior.

Perplexity brings its local Portable Computer agent to Windows RTX PCs

Perplexity released Portable Computer for Windows on NVIDIA GeForce RTX and RTX PRO systems with 24 GB or more of memory, extending a local version of its Computer agent that plans and carries out multi-step tasks on-device. A bundled local model based on Qwen handles file-spanning analysis and recurring work without spending cloud credits, while sensitive data stays on the machine and harder research can still escalate to cloud models. Setup ships preconfigured instead of asking users to pick models and wire up the inference stack themselves.

For builders, the signal is that capable agents are becoming a PC feature rather than a cloud subscription: routine work stays local and private, frontier models handle only the overflow. Confirm your GPU meets the memory bar and test how much of your own workflow truly completes without escalation.

Black Forest Labs releases FLUX 3 Action, an open 7B robotics action model

Black Forest Labs released FLUX 3 Action, an open model that consumes multi-camera video from a robot workspace and predicts the next action plus the expected change in the scene. It builds on the multimodal FLUX 3 backbone trained across video, image, and audio, and the company reports a record RoboLab-120 success rate at 7 billion parameters with much faster inference than the prior best open model. Weights are published on Hugging Face, with games and computer-use agents mentioned as nearby testing grounds.

For builders, the appeal is a small open checkpoint aimed at on-device control loops where latency matters more than chat fluency. Treat the leaderboard claim as vendor-reported until independent runs confirm it, and test on your own embodiment before assuming transfer.

Read the full story at The Decoder (September 24, 2026).

Q.ANT opens a photonic SDK with a laptop-ready CPU simulator

Q.ANT published its Native Computing Toolkit under a commercially permissive license with Python and C APIs, samples, benchmarks, and docs for its light-powered NPUs. The key piece for adoption is a CPU simulation backend: developers can write, test, and benchmark photonic inference code on an ordinary laptop today and run the same API against real hardware later through research centers, cloud access, or a rack-mount unit. The first release targets inference such as image classification, ships without a native PyTorch plugin, and bundles the company's own classical-versus-photonic benchmark comparisons.

The strategy directly targets the ecosystem gap that sank prior chip challengers: make the programming model usable before hardware is widely available. If you evaluate it, rerun the efficiency claims on your own workloads and budget integration work for the missing framework plugin.

Darktrace shows poisoned history can turn coding harnesses into attackers

Darktrace researchers demonstrated conversation-history poisoning against common agentic harnesses, where a malicious package plants a fabricated transcript that convinces the agent it is an authorized red teamer. Because history files live on the workstation without integrity checks, the agent can proceed from reconnaissance through lateral movement to domain impact in a lab, with model guardrails varying by model and harness. The team disclosed to the affected vendors in August and recommends cryptographic signing plus server-side verification of returned messages.

The operator lesson is concrete: vet MCP servers and harness plugins like production dependencies, limit what credentials an agent process can reach, and watch for agents doing network reconnaissance they were never asked to do. History integrity is now part of the agent attack surface, not just prompt content.

Semaphore puts CI/CD behind sem-ai, an agent-first CLI with MCP

Semaphore released sem-ai, an open-source agent-first interface that lets coding agents set up pipelines, run tests, read failures, and iterate against real CI feedback. It combines a CLI with an embedded MCP server so tools such as Claude Code and Codex can query pipeline status and configs without leaving the agent loop, while teams choose where agents act alone and where approvals stay. The pitch is that verification, not generation, is the bottleneck as agents write more code.

For automation builders, the pattern is worth copying even without the product: give agents structured access to pipeline results and require green runs before merge. Confirm stack coverage for your language and runner before wiring it into delivery paths.
