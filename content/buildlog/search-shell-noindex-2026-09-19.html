The search page is a script driven shell: the server sends an empty result list and the browser fills it in after fetching the offline index. That shell carried a canonical address and a map entry, inviting crawlers to spend attention on a page with no readable text. It now carries a noindex directive while staying reachable for readers, and the map file lists only pages with real prose. Browse the journal or the build log for the pages crawlers should prefer.

Motivation

Crawl attention is finite, and an empty shell with a canonical address plus a map entry competes with real writing for that attention. The shell exists for readers who type a query, not for indexers, so the index should point at articles and log entries instead. Removing the shell from the map and asking crawlers not to index it directs that attention back to substantive pages.

What changed

The page renderer gained an optional crawl directive slot that stays empty unless set, so every existing page builds exactly as before. The search page sets the slot to ask crawlers not to index it while still permitting link following, and the map file no longer lists the search address. The structured data kind on the search page is unchanged, since the schema still describes what the page is, and the robots file is untouched so the shell stays reachable.
