Every page on the journal now carries a single verification loader in the document head, placed after the site script and before the closing head tag. The snippet is plain markup with no builder placeholder, so the static builder passes it through untouched, and no ad units or placements ship in this change.

Motivation

The ad platform asks publishers to prove control of a site by serving a verification loader from every page head. Adding that loader unlocks the approval flow while leaving layout, reading order, and the existing design exactly as they were.

What changed

The shared head template now ends with one async loader element after the site script. Because every page renders through that shared template, the home page, each article page, and the build log index all serve the loader without further edits, and the artifact test now permits exactly that one outside script while still rejecting any other remote source.

How it was done

After confirming the private remote and login, development worked on a short-lived feature branch from the fresh main line. The loader line went directly after the site script line in the shared template, then the site was rebuilt and the home page, one article page, and the build log index were checked for the exact loader markup before the suite and the presence gate were run.

Verification evidence

The deterministic build exits success, the full test suite is green, and the presence gate prints success with this entry covering the change. The built home page, a sample article page, and the build log index each contain the loader line exactly once, and a scan of the diff finds no secrets. The added loader is async, so its page-weight delta is one outside script, noted here without blocking release.
